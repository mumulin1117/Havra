接入说明
本项目共 6 个接口，原始与混淆 URL 是同一个接口的两种入口。正式接入使用混淆 URL。
接入顺序：Open启动 → 输入邮箱密码并点击下一步 → 新老用户校验 → 下方三种模式对应步骤；三种模式共用本项目的6个接口及同一套路径、字段、Header混淆。取消时调用拒绝或取消认证。
项目认证方式由后台配置，创建会话时固定；接口不返回verificationMode，前端按项目预先约定流程。仅活体模式跳过照片上传，Result无需referenceImageId，仅判断AWS完成状态和活体阈值；照片比对模式保持原流程；仅人像模式上传正脸照片并通过质量检查即可完成，不创建AWS活体会话、不做人脸比对。两种活体模式的AWS参考人像自动保存为活体抓拍，与用户上传照片一起展示，重复查询不重复存图；图片保存重试与认证判定分开。
AWS SDK 操作在客户端完成，不是新增的后端接口。全流程保持同一 appId、deviceNo；版本记录本次客户端值，升级不要求重新认证。

三种认证模式接入指南
模式由后台项目开关控制，创建会话时保存模式快照；客户端请求不传verificationMode，创建响应也不返回该字段。前端须事先与项目配置约定模式；切换只影响新会话，已有会话继续按创建时的模式完成。无需生成第二套混淆方案，已有别名保持不变；完整方案重新下载TXT即可取得本说明。
统一入口顺序：Open（启动，不带邮箱）→ 显示返回H5 → 用户输入邮箱、密码并点击下一步 → user-status（新老用户校验）→ 新用户进入下面对应模式；老用户调用带邮箱的Open登录入口。认证成功后的Result已交付H5/token，无需立即再请求Open。
本说明保留现有业务：user-status只判断本项目内设备号是否命中成功历史，并优先匹配配置测试账号；不验证密码、不按账号值匹配普通用户成功历史、不把当前新设备写成VERIFIED。Open仍按设备真实认证、测试账号及版本/兜底规则返回，普通账号换到新设备仍按新用户处理；以实际返回为准。Open的isNewUser也可能来自版本拦截或第三方兜底，不要据此反复要求已认证设备重做认证，避免循环跳转。

模式一：活体＋照片比对（LIVENESS_AND_COMPARE）
1. 应用启动调用Open：POST https://www.havraaurora.store/casual9/daily/feelings/people/daily，JSON {}；此时不带email/password，pushToken可选。携带公共Header followRegionalBrowse=<本项目appId>、voicesMomentsMemory=<本次客户端实际版本，不带v>、sharingAuthenticMemory=<固定设备号>。按返回h5Url展示页面，longtoken内部第三方字段不改写。
2. 输入账号（邮箱或用户名）、密码后点击下一步，先校验新老用户：POST https://www.havraaurora.store/smile9/friends/feelings/meetup；沿用相同appId/appVersion/deviceNo，JSON：
{
  "photosBrowseMemory" : "user@example.com"
}
该请求不传password，也不传verificationId；该阶段尚未创建认证。响应示例（新用户）：
{
  "momentsAuthenticFollow" : 0,
  "activityEverydayLocal" : "ok",
  "sceneFriendshipCall" : true
}
普通非空账号（邮箱或用户名）登记或更新设备注册资料和进度，只录入邮箱不算认证成功；测试账号跳过普通登记。
分支A：code非0或HTTP失败，显示英文message，停留当前页面，不继续创建认证。
分支B：isNewUser=false（老用户或测试账号），跳过后续人脸步骤，调用Open登录入口：POST https://www.havraaurora.store/casual9/daily/feelings/people/daily，JSON：
{
  "photosBrowseMemory" : "user@example.com"
}
pushToken可选，依旧不传password；以本次Open实际h5Url/longtoken为准。相同账号换到新设备仍需要认证；Open可能仍返回本地页，不在前端自行绕过认证或无限循环调用。
分支C：isNewUser=true，经用户明确同意后才按下方步骤创建认证；邮箱、密码只在页面内存暂存，后续Result提交email/password（password沿用可选规则），不放入URL/localStorage/日志。Open/user-status不校验密码，老用户分支不通过这两个接口保存密码；Result只保存密码哈希，不实现账号密码登录。
3. 创建认证：POST https://www.havraaurora.store/follow2/journey/companions/companions，JSON：
{
  "togetherDailyCircle" : true
}
保存verificationId，sessionId/region/identityPoolId交给AWS SDK。
4. 上传正脸照片：POST https://www.havraaurora.store/call3/chatting/photos/interest，Content-Type=multipart/form-data；额外Header circleLocalDaily=<verificationId>；表单 sharingDialogueFollow=<本项目appId>、placesCasualConnection=<客户端实际版本>、photosMeetupPeople=<正面单人照片文件>。保留images中的imageId；照片质量检查未通过时重新拍摄上传。
5. 客户端使用AWS SDK完成视频活体（不是后端HTTP接口）。
6. 查询Result：POST https://www.havraaurora.store/smile6/together/dialogue/lifestyle/warmth，首次Result JSON最小示例：
{
  "placesAuthenticTogether" : "<创建返回的认证ID>",
  "storyFeelingsCall" : "<上传返回的imageId>",
  "photosBrowseMemory" : "<下一步时填写的邮箱>",
  "videoMomentsBrowse" : "<页面暂存的密码，可选>"
}
必须使用用户上传照片的imageId，不能用AWS活体抓拍代替；绑定成功后重查可省略referenceImageId。后端检查活体并比对用户照片与AWS参考人像，两项均通过才认证通过。

1. 登录入口路由
============================================================
方法：POST
原始完整 URL：https://www.havraaurora.store/client/face-verification/open
混淆完整 URL：https://www.havraaurora.store/casual9/daily/feelings/people/daily
Content-Type：application/json
Header：使用公共 Header
用途：按项目和设备返回H5入口及Token；每次先实时获取Token，失败或无效才读有效缓存。测试账号优先于版本拦截，Open命中版本拦截返回isNewUser=true及本地第一个页面；Result认证成功命中拦截返回isNewUser=true及本地第二个页面。两者均实时优先，不使用缓存URL。不校验邮箱/密码，不作为独立账号登录认证。
请求字段（JSON）（原字段 | 混淆字段 | 类型 | 注释 | 要求）
pushToken | companionsHarmonySharing | string | 请求可选；有值才转发第三方 | 可选
email | photosBrowseMemory | string | 可选，最多254字符；兼容邮箱或用户名；Open保存登录账号并匹配测试邮箱，result保存注册账号；不转发第三方 | 可选，保存设备登录邮箱，并匹配该项目配置的Apple测试账号邮箱
Open email按appId+deviceNo保存为独立登录账号；未传/null/空白保留原值，不覆盖注册资料或认证快照。配置测试账号忽略首尾空白和大小写匹配，命中返回isNewUser=false、本地第二个欢迎页；Token始终实时优先，失败才用有效缓存，两者皆无则503。忽略第三方URL，不写VERIFIED，不触发AWS。普通账号不证明设备已认证；Result email用于绑定注册资料，二者用途不同。
混淆请求示例（公共 Header 已携带身份，可直接传空 JSON）：
{}
返回字段（原字段 | 混淆字段 | 类型 | 注释 | 要求）
code | momentsAuthenticFollow | integer | 返回；0表示处理成功，非认证结论 | 总是返回
message | activityEverydayLocal | string | 返回；提示文本，不可代替认证判定 | 总是返回
isNewUser | sceneFriendshipCall | boolean | 返回；本次入口标记；测试账号false，版本拦截和老用户重试后的兜底true，正常实时老用户false；不等于数据库认证状态 | 总是返回
h5Url | photosLocalCompanions | string | 终态/Open返回；加载页、欢迎页或第三方URL | 总是返回
longtoken | videoBondTopics | object（成功时非空） | 返回；无有效Token时返回503；外层混淆，第三方对象内部保持原样 | 总是返回
未认证设备：isNewUser=true、本地第一个注册页面、实时Token优先；实时失败才用有效缓存Token，无有效Token返回503。
普通老设备：最多3次失败重试，共用本次幂等键；取得有效Token就停止，缺URL不重试。实时URL和Token均有效返回false及本次URL/Token；实时Token有效但无URL返回true、本地第一页及本次Token。实时失败仅有效缓存Token兜底，返回true及本地第一页；没有有效Token返回503。不使用缓存URL，不删除VERIFIED。
混淆响应示例（未认证设备）：
{
  "momentsAuthenticFollow" : 0,
  "activityEverydayLocal" : "Please register and complete face verification.",
  "sceneFriendshipCall" : true,
  "photosLocalCompanions" : "<配置的加载页>",
  "videoBondTopics" : {
    "clientId" : "<第三方原值>",
    "capability" : "<第三方原值>"
  }
}

2. 创建认证会话
============================================================
方法：POST
原始完整 URL：https://www.havraaurora.store/client/face-verification/session

Header：使用公共 Header
用途：用户明确同意后创建认证流水；仅人像不创建AWS活体会话，另外两种模式同时创建AWS会话。
请求字段（JSON）（原字段 | 混淆字段 | 类型 | 注释 | 要求）
consent | togetherDailyCircle | boolean | 请求；明确同意生物识别，必须true | 必填，必须 true

{
  "togetherDailyCircle" : true
}
返回字段（原字段 | 混淆字段 | 类型 | 注释 | 要求）
code | momentsAuthenticFollow | integer | 返回；0表示处理成功，非认证结论 | 总是返回
message | activityEverydayLocal | string | 返回；提示文本，不可代替认证判定 | 总是返回
verificationId | placesAuthenticTogether | string | 会话返回/结果请求；认证记录ID | 认证流水

公共错误与接入注意
HTTP400参数错误；404记录/项目不匹配；429频率限制（Open独立防护不扩展到Result）；503表示无有效Token、必要配置缺失或识别/交付暂不可用。HTTP状态码不混淆，识别到别名时code/message也使用别名。
错误示例（HTTP400）：
{
  "momentsAuthenticFollow" : 400,
  "activityEverydayLocal" : "email must be a string"
}
code=0 仅表示接口处理成功，不等于认证通过；活体＋照片比对模式要求AWS活体和照片比对均通过；仅活体模式只要求AWS活体通过，不调用照片比对；仅人像模式只要求本次上传照片的人脸质量检查通过，不代表真人现场采集或身份匹配。
普通设备 Open 下游异常兜底：实时失败/Token无效才使用同appId+deviceNo且版本、pushToken、第三方地址及参数配置匹配的有效缓存Token。Open普通用户兜底为true及本地第一页，测试账号仍false及第二页；Result认证成功后兜底为true及第二页。实时有效Token更新缓存，失败不覆盖，读取不续期，过期不用；无时间字段最多270秒，有时间字段提前30秒，最长缓存24小时。不存取缓存URL。实时和缓存均无有效Token则503，不返回null Token成功。isNewUser只是本次入口标记，不撤销认证成功历史，不据此循环要求已认证设备重新注册。必要页面缺失仍503。
longtoken 只混淆外层名称，内部第三方 token 的 keyName、nonce、ttl、mac、capability、timestamp 等名称和取值保持原样。
pushToken <=512字符；未传不补历史值，有值才转发第三方。项目停用后禁止访问人脸流程，历史版本状态不作为准入条件。
